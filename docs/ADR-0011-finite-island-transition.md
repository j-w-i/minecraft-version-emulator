# ADR 0011 — explicit finite-island exterior transition

Status: implemented; bounded core-repair acceptance recorded 2026-10-16. Full production/client/crash certification is not claimed. The narrow exception below supersedes the earlier blanket statement that upgrade regions never change; it does **not** authorize regenerating player terrain. Current operator handoff: [Indev→Infdev repair](<INDEV-INFDEV-REPAIR.md>).

## Problem and verified cause

The pinned Moderner Beta 5.0.0-alpha.4+1.21.1-fabric finite provider generates out-of-bounds chunks as a synthetic apron: bedrock at Y 0–53, dirt at 54, source water at 55–63, then air to 127. Merely releasing the saved world border preserves that bedrock/dirt apron. It becomes an artificial obstruction when the generator advances to Infdev.

The finite footprint for the project's default Indev preset is X/Z -128 through 127. The implementation does not reconstruct Moderner Beta's finite or infinite terrain algorithm.

## Decision

During an **explicit finite-to-infinite upgrade**, while the world is closed/locked and before chunk-position bookkeeping:

Precondition (current schema 3): bind the plan to the exact saved 64-bit seed, a SHA-256 of the immutable initial historical revision, and a recognized finite source preset. All three source provider-settings objects must contain only the preset reference; inline overrides cannot be assumed to have the default 256x256 geometry. Missing/wrong-type seed or metadata fails before staging backups or changing regions. Read/recovery/runtime attachment recheck the seed and origin. Legitimate clones/renames and later version revisions retain identity, but an unrelated same-seed world with a different origin does not. Old unbound development schemas 1/2 are refused rather than silently trusted; none were deployed to personal saves. This checks stored inline settings, not arbitrary external datapack replacements of named presets.

1. Inspect the Overworld Anvil data, not a loose bedrock/dirt search.
2. Preserve every island chunk unconditionally.
3. Release an exterior chunk only if **all 32,768 blocks, including air, equal the pinned default synthetic apron**, with no block entities, saved entities, occupied entity-region entries or POI records. Unsupported formats and edited exterior chunks are retained/refused, never guessed away.
4. Stage immutable complete before/after region images, force writes, and verify SHA-256. Persist a PREPARED plan before replacing anything. Changes clear only the released slots' location/timestamp headers: retained compressed blobs remain byte-identical. No repacking of retained chunks.
5. Recovery preflights every before/after backup and current-region hash. Accept exactly before or after, reject unexplained changes. Replace atomically, then mark COMPLETE. Keep the backups.
6. Persist the exact source-terrain chunk set, including protected edited exterior chunks. Future worldgen cannot write to those chunks: both `WorldGenRegion.setBlock` and `ensureCanWrite` are gated. The second matters because vanilla OreFeature writes sections directly after checking `ensureCanWrite`; a setBlock-only hook misses it. Normal server/player writes are unaffected.
7. Store sampled boundary solid heights in the plan. Only boundary chunks with terrain-stage status are sampled; an empty biomes-stage placeholder is **not** a height-zero shoreline.

Future exterior terrain receives a 64-block smooth coast collar using Moderner Beta's **own density-modifier extension point** (`ChunkProviderNoise.isDensityModified` / `modifyEdgeDensity`), after upstream interpolation and before block placement/surface/features. It blends from the sampled shoreline to untouched upstream density. This is compatibility shaping, not a replacement terrain generator and not generation followed by content deletion.

The plan is attached to the specific historical Overworld generator, not a process-global active session. Fresh Infdev and ordinary worlds without a plan retain their normal density. The island footprint is never blended. Unknown edge columns use upstream density unchanged, rather than inventing source geometry. A fresh version recipe is not retroactively edited by this migration.

## Preservation limits and outstanding acceptance

- A modified exterior chunk may retain part of the wall, intentionally. Preserving a build is more important than forcing a visually perfect shoreline.
- Inventory/player files, island blocks and entity/POI files are never migration write targets. Region backups include even the pristine exterior data that is released.
- Empty zero-byte entity-region handles are valid vanilla output; other truncated/corrupt regions fail closed.
- Already-upgraded worlds **do not** get an unsolicited cleanup on ordinary load. The explicit `/hex repair-finite-edge` path below requires matching verified backup provenance; no personal save has been edited.
- Additional acceptance is still owed: full-perimeter/corner sampling across more seeds, actual player login/actions, broader originally-biome-converted worlds and process-crash injection. Edited exterior blocks/chest inventory, an Infdev-biome exact-pattern negative and synthetic saved-player file preservation now pass the bounded runtime below. Schema-3 identity and inline-setting refusal do not authenticate arbitrary external datapack preset definitions. Unit tests and a successful launch alone do not establish a seamless coastline.
- Initial isolated runtime exposed the empty-region compatibility issue and a second issue in height capture (biomes placeholders); both were corrected with regression coverage/stricter status checks. Intermediate fixtures `sol-indev-edge-v1` and `sol-indev-edge-v2` are NOT final seam acceptance. The v2 saved-block comparison additionally caught 178 ore/dirt/gravel writes spilling into one source island chunk during future decoration. That real preservation failure led to the source-terrain write protection above, and the development plan schema advanced to 2 (no schema-1 plan was deployed to personal saves).

## Explicit repair of an already-upgraded world

`/hex repair-finite-edge` (operator permission level 2) stages **intent only**. Stop/restart normally; it is not a live chunk regeneration command and `/hex recover` must not be repurposed to run it while chunks are open. No version revision is appended. Keep a separate full-world archive before administrative changes.

Repair requires exactly one matching, fully hash/size-verified historical backup containing both metadata and `level.dat`. It must prove default finite source settings, the same full seed/origin, an exact history prefix and the following explicit finite-to-infinite action. Missing, corrupt, foreign or ambiguous provenance refuses, never guesses. Current metadata and all three saved generator references must agree on an infinite historical destination. Request pins metadata and backup-manifest hashes; execution verifies everything again. Version upgrades and pending repairs cannot interleave.

Execution runs under the storage lock before world decode, or reacquires it after normal shutdown closes the worlds. It reuses the same exact-pristine-only region transaction and protects all other current terrain, including edited exterior chunks. The request remains pending after region completion until released coordinates are withdrawn from the old biome conversion mask. Pruning keeps every other bit and every other JSON field, preserves a forced hash-verified original record, writes atomically, and is idempotent. Corrupt records/backups refuse; a partial repair cannot be silently loaded. A COMPLETE request remains as an audit record and does not block later upgrades.

[Repair implementation](<../src/main/java/net/historicalexperience/world/upgrade/FiniteEdgeRepair.java>), [repair regressions](<../src/test/java/net/historicalexperience/world/upgrade/FiniteEdgeRepairTest.java>) and [biome pruning regressions](<../src/test/java/net/historicalexperience/world/upgrade/BiomeRecordRepairTest.java>) cover stage-only behavior, edited blocks, history/metadata preservation, missing/corrupt/foreign/ambiguous backup refusal, re-verification, concurrent upgrade refusal, crash retry between region and biome commits, negative coordinates, unknown fields and corrupt pruning-backup refusal.

Bounded runtime: replica `sol-indev-old-edge-repair-v2` was reconstructed **only in a new project fixture** from immutable verified before-images using [the diagnostic fixture builder](<../scripts/prepare-old-finite-fixture-1211.py>). It is not an operator repair tool. The source dedicated-server fixture had no optional GUI biome-conversion record; the replica explicitly adds a diagnostic old-census record, disclosed in [replica provenance](<../logs/sol-indev-old-edge-repair-v2-old-replica.json>). The real operator command returned 1, left the repair pending and created **no terrain plan while live**. Normal shutdown completed under the lock: **185** apron chunks released and **185** old biome positions withdrawn (**1521 to 1336**), all other biome fields unchanged, metadata bytes identical. After restart **256** island chunks retained their decoded blocks/containers; **96** sampled shoreline pairs had **zero height difference** and **zero bedrock at Y8+**. [Command evidence](<../logs/sol-1211-sol-indev-old-edge-repair-v2-reload-repair.json>), [completed repair log](<../logs/sol-1211-sol-indev-old-edge-repair-v2-reload-repair.log#L126>), [saved comparison](<../logs/sol-indev-old-edge-repair-v2-finite-check.json>). Build/licence artifacts and **623 automated tests** pass; final preflight additionally checks recipe ownership so an infinite metadata profile cannot disguise a still-finite stored recipe. That earlier fixture did not cover edited-exterior/container/player data; the subsequent bounded result below does. Process-crash injection and actual player login remain outstanding; no personal save was used.

Per-chunk saved evidence is now additionally required by [FiniteChunkEvidence](<../src/main/java/net/historicalexperience/world/upgrade/FiniteChunkEvidence.java>). It decodes all **512 used biome cells**, not just palette membership: default native Indev normal/out-of-bounds void are supported. Actual pinned-provider saves have mixed normal/void cells in boundary chunks. A rewritten biome table must match the existing biome converter's result AND have a real nonnegative LONG `LastUpdate` no newer than the verified original backup's LONG `Data.Time` (monotonic game time, not player-set day time). Missing/wrong-type time is never guessed as zero. A later/overwritten conversion census is NOT origin evidence. A destination-native Infdev block-for-block replica is retained.

Unknown root/section/container attachments, occupied entity/POI data, structures, scheduled ticks, malformed/missing/duplicate biome sections and unsupported status/metadata are retained. Finite-provider prefilled protochunks are valid: vanilla status may still be `structure_starts`, with empty carving masks and packed-short postprocessing queues despite the complete synthetic block/biome table. Those known generation caches are validated, not mistaken for player data. These checks are repeated against EVERY immutable prepared before-image, including older development plans, and current entity/POI occupancy is rechecked before ANY region write. Valid checksums alone do not authorize a slot deletion. [Evidence regression tests](<../src/test/java/net/historicalexperience/world/upgrade/FiniteChunkEvidenceTest.java>) and [prepared-plan/converted-time regressions](<../src/test/java/net/historicalexperience/world/upgrade/FiniteEdgeRepairTest.java>) exercise these boundaries.

Limits remain explicit: this is conservative encoded-save evidence under normal monotonic game time, not a cryptographic creation receipt against deliberately forged NBT/native-biome replicas or manually reset game clocks. Converted genuine chunks saved after the staging backup's clock may be retained even if they predate the actual switch. Unsupported evidence is retained with a warning, potentially leaving part of the wall. It must not be silently guessed or cleared to improve appearance. External datapack preset definitions remain unauthenticated.

### Bounded edited-exterior result (638 automated tests)

Fixture `sol-indev-old-edge-build-v5` now passes real preparation, actual command staging, normal locked stop, restart and independent saved-state comparison. [Preparation](<../logs/sol-1211-sol-indev-old-edge-build-v5-reload-prepare-build.json>) places nine cobblestone platform blocks and a chest containing **seven diamonds** in exterior chunk 8,0. A separate chunk 9,0 retains the exact 32,768-block apron table but is explicitly changed to **512 used Infdev biome cells**: a negative case that must NOT be released. It also writes an explicitly synthetic saved-player NBT sentinel containing eleven diamonds; this is file-preservation evidence, **not a real player login/inventory interaction test**. [Fixture code](<../src/main/java/net/historicalexperience/server/FiniteRepairFixtureVerification.java>) is opt-in and requires a newly-created owned diagnostic replica receipt.

[Actual repair](<../logs/sol-1211-sol-indev-old-edge-build-v5-reload-repair.log#L125-L127>) releases **183** chunks, retains both protected chunks, and withdraws exactly **183** old biome positions (**1521 → 1338**), preserving all other record fields and metadata bytes. [Restart verification](<../logs/sol-1211-sol-indev-old-edge-build-v5-reload-far.json#L346>) checks the platform/chest count, every replica block and biome cell, and the player-file SHA-256. [Independent saved comparison](<../logs/sol-indev-old-edge-build-v5-finite-check.json>) proves all **256** island chunks and both exterior block/container/biome digests unchanged, and the saved player data byte-identical. **160** eligible shoreline pairs (**112 east, 48 south**) have zero height difference and zero bedrock at Y8+. **16** columns in the deliberately retained build chunk still have the original wall and are reported separately, not silently accepted as regenerated terrain. This does not prove full-perimeter/corner coverage. The 1105 other retained exterior entries are mostly protochunk placeholders, not 1105 builds.

The verifier uses versioned canonical digests (v2 normalizes absent-air representation); it decodes used biome cells independently for the protected exterior chunks and hashes saved player files. Existing v1 evidence remains readable. Only the two explicitly source-snapshotted, identity-verified retained chunks are exempt from the regenerated-wall assertion; that assertion was not weakened for unknown failures. A fresh [ordinary control](<../logs/sol-1211-sol-early-ordinary-control-v2-fresh.json>) retains vanilla generation, no historical metadata, ladder output three, zero suppressed decoration writes, and no fixture effects. Build/licence artifacts, **638 tests** (zero failures/errors/skips), and whitespace checks pass. No personal world/client deployment.

Intermediate failures are not acceptance: build-v3's new marker was accidentally addressed to the source project fixture, causing the owned-target guard to refuse before placing anything. That one newly-created diagnostic marker was content/path-verified and removed; source game data was not changed. The builder now confines the marker to the NEW target and fingerprints every source world file except the held session lock, with an explicit unchanged-source receipt and symlink refusal. Build-v4 correctly preserved the build/player data but failed the wall assertion because an initially over-strict FULL-only metadata check rejected valid prefilled finite protochunks. Actual saved statuses, empty carving masks and packed postprocessing queues were inspected; support and regression coverage were added, then build-v5 was reconstructed from the original verified source. Neither failed intermediate is coast acceptance.

The first diagnostic attempt exposed two verifier assumptions, not silently accepted failures: an optional biome record was assumed present, and snapshot verification required an already-existing transition plan, which an old world cannot have. The builder now labels its synthetic census explicitly; the offline snapshot independently checks backup hashes, same seed, default settings and a matching history prefix, without requiring a plan. Island equality and wall/seam assertions were not relaxed.

All **256 island chunks** retain identical decoded block states and block entities. **185** exact apron chunks were released; all **1024** source boundary heights were available. **96** exterior shoreline columns sampled after regeneration had **zero height difference** and **zero bedrock blocks at Y8 or above**. The 1080 retained exterior entries are mostly empty protochunk placeholders, not 1080 player builds.

It preserved all **256** island chunks, released **185** pristine apron chunks, captured **1024** edge heights, and found **128** saved shoreline pairs with **zero height difference** and **zero bedrock at Y8+**. The persisted identity retains the full signed 64-bit seed exactly and passes the runtime seed check after restart.

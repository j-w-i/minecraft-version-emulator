# Adversarial architecture review

**Verdict: revise before implementation.** The typed-gate direction is sound; the contract is not yet a semantics-preserving implementation specification. Review is static, against the actual source and both audits. No Gradle, compilation, game launch, or source modification was performed. Only this report was written. Runtime conclusions below distinguish reachable code from observed gameplay.

## MUST-FIX before implementation

### M1 — Freeze answers, not historical intentions; specify polarity and exceptions

The proposal's “every feature is an inactive-in-ordinary-world deviation” is a useful *new primitive*, not a drop-in replacement for every public predicate. The current API has capabilities, deviations, identity checks, data queries, and world resolvers. A mechanical rename or negation changes answers.

**Exhaustive exceptions within the reviewed gate API to a literal “same predicate, false ordinary, milestone windows” conversion:**

* `functionalEnchanting`, `sneakingAvailable`, `functionalBrewing`, `endPortalFunctional`, `experienceLevelShown`: true for null **and unknown ids**. Keep capability adapters as complements of negative historical deviations; they are not themselves false-default features.
* `netherAvailable`, `foodStacks`: currently false for null/unknown; correcting them through negative features is an intentional API change as well as a mixin fix (M2).
* `enchantingTableExists`: false for null/unknown despite the modern table existing. Either retain it explicitly as “declared historical version has table”, delete the unused API, or approve an additional change. Do not hide a third null-default change inside P3.
* `experienceOrbSpawnDisabled`: `!rules.awardsExperience` for the resolved world; not a timeline rule. Keep a data-derived query, or derive a bit from the per-version rules, not from a window.
* `olderThanVersion`: parameterized comparator, not one feature. Keep as a typed comparison utility if needed; do not invent a feature for arbitrary arguments.
* `isDeclaredVersion`/`isDeclaredWorld` and public `preBeta18`: membership helpers, not arbitrary version-position queries. `preBeta18` directly calls the immutable set's `contains` without a null guard; include its exceptional null behavior in characterization rather than assuming every helper returns false.
* Every `Level` overload resolves **ServerLevel only** and returns an ordinary/null answer on ClientLevel. Replacing it with the global session facade changes the resolver semantics even if its version table is perfect. Inventory/level-free calls may use the session; world-aware calls must keep their explicit context.
* `jumpExperienceBug` amount and `eraArrowSpeedPercent` are algorithm/value APIs (random1–100 or zero; constant70), not boolean windows. Keep them in mechanics; gate only the decision to invoke them.

Evidence: [resolver and helpers:203–223](../../src/main/java/net/historicalexperience/gameplay/HistoricalGameplayTweaks.java#L203-L223), [preBeta18:70–88](../../src/main/java/net/historicalexperience/gameplay/HistoricalGameplayTweaks.java#L70-L88), [data flag:996–1003](../../src/main/java/net/historicalexperience/gameplay/HistoricalGameplayTweaks.java#L996-L1003), [value/random APIs:1124–1156](../../src/main/java/net/historicalexperience/gameplay/HistoricalGameplayTweaks.java#L1124-L1156).

Outside that class, availability is not runtime activation: client toggles, item/stance state, texture-layer priority, and generation-revision data remain extra conditions. For example [canBlock:57–65](../../src/main/java/net/historicalexperience/gameplay/HistoricalSwordBlocking.java#L57-L65) needs an empty offhand AND a sword; [lighting refresh:131–138](../../src/main/java/net/historicalexperience/client/lighting/HistoricalOldLighting.java#L131-L138) combines availability with a persisted toggle. A feature bit must not erase those conditions. Conversely, union-of-windows is sufficient for the reappearing version label; this is not a reason to introduce general boolean-expression dispatch on hot paths.

### M4 — Specify an implementable, initialization-safe pure core BEFORE S1

* The proposed record has the listed components but also a per-instance precomputed EnumSet. Java records cannot declare additional instance fields. Choose a private immutable compiled-feature carrier component, an immutable class, or a version-keyed external cache. Never expose a mutable EnumSet through an automatically generated record accessor. Pin record equality/hash semantics if adding derived components.
* Moving constants alone cannot satisfy the stated dependency rule. The current [GenerationRevision:123–130](../../src/main/java/net/historicalexperience/version/HistoricalVersion.java#L123-L130) contains `HistoricalFeatureExclusions.Exclusion` and `BetaOreRules.OreRule`; [VersionRules:188–197](../../src/main/java/net/historicalexperience/version/HistoricalVersion.java#L188-L197) contains `HistoricalLootRules.DropRule`. Their carrier types must move to pure data ownership too (with provenance retained), or the “version imports nothing / legacy imports version only” rule remains false. `HistoricalVersions` currently imports four domain data owners ([26–33](../../src/main/java/net/historicalexperience/version/HistoricalVersions.java#L26-L33)).
* Feature/Milestone constructors/static initializers must **never resolve bounds through `HistoricalVersions.byId/all()`**. Construction chain `HistoricalVersions → LegacyCatalog → HistoricalVersion → FeatureTable → HistoricalVersions` sees partially initialized ALL/BY_ID. Eager Feature→Milestone→registry can fail even earlier. The existing consumers already derive one-time static tables: [marker:163–164](../../src/main/java/net/historicalexperience/HistoricalMarker.java#L163-L164), [profiles:110–145](../../src/main/java/net/historicalexperience/profile/HistoricalProfiles.java#L110-L145), [pre-Beta set:70–73](../../src/main/java/net/historicalexperience/gameplay/HistoricalGameplayTweaks.java#L70-L73). A partial/empty observation can be permanent, not just an exception.
* Require fresh isolated classloader/process permutations: Feature first, Milestone first, registry first, marker first, profiles first; assert complete identical tables, not merely “Feature alone loads”. Pure-carrier extraction belongs before or within the foundation step, not postponed until S5.

### M5 — A faster global pointer is not a world-context contract

[Proposal:67–72](target-architecture.md#L67-L72) retains the single volatile global with both server and client writers; this does not address the [debt audit's cross-side warning](debt-and-coupling.md#L185-L193). Server sets it only at **player JOIN**, not world start ([sync:80–96](../../src/main/java/net/historicalexperience/server/HistoricalVersionSync.java#L80-L96)); client payload/disconnect also writes/clears it ([client:51–62](../../src/main/java/net/historicalexperience/client/HistoricalClientRules.java#L51-L62)). Therefore it may be null while a historical dedicated world is ticking before any join. A volatile ref guarantees publication, not correct lifecycle, side, or per-level ownership.

Do not mechanically migrate explicit ServerLevel/generator rules to this facade. Specify world-aware resolution, generator-first/scope-fallback precedence, and side ownership now. Either defer only the pointer representation change until S6, or freeze old context behavior in tests and explicitly exclude world-aware paths from S2. Keep snapshot selection identity separately: [client:51–55,65–71](../../src/main/java/net/historicalexperience/client/HistoricalClientRules.java#L51-L71) intentionally resolves baseline gameplay and retains exact snapshot overlay independently.

### M6 — Resolve Mixin/accessor and side rules before package moves

Keeping JSON `package` unchanged is compatible with moves **only if** every entry becomes the matching relative dotted name, e.g. `common.combat.PlayerHistoricalCombatMixin`, and Java package/imports are changed together. Descendants remain under the transformer-owned package. It does **not** make ordinary helpers loadable there. The project has a real historical IllegalClassLoadError, documented in [food helper:28–45](../../src/main/java/net/historicalexperience/gameplay/HistoricalFoodStackLimit.java#L28-L45).

The proposal silently weakens the current blanket “nothing outside mixin references it” wording to an accessor exception ([135–139](target-architecture.md#L135-L139)). This exception must be explicit and tested: legitimate `@Accessor/@Invoker` interfaces are not ordinary helper classes. [CreativeScreenProbeAccess:4–12](../../src/main/java/net/historicalexperience/mixin/CreativeScreenProbeAccess.java#L4-L12) is an instance invoker used via casts by [SnapshotAnvilProbe:228–232](../../src/main/java/net/historicalexperience/client/version/SnapshotAnvilProbe.java#L228-L232). [NaturalSpawnerProbeAccessor:51–72](../../src/main/java/net/historicalexperience/mixin/NaturalSpawnerProbeAccessor.java#L51-L72) is a **static invoker** called by [GenerationVerification:701](../../src/main/java/net/historicalexperience/server/GenerationVerification.java#L701) and [746](../../src/main/java/net/historicalexperience/server/GenerationVerification.java#L746). Moving these requires updating ordinary imports/FQNs and keeping registration while those probes execute. Disabling their mixins without guarding callers leaves missing interface implementations or the explicit AssertionError stub. Moving the interface outside the owned package without a deliberate new config is not a shortcut.

**Audit correction:** the alleged four client-*targeting* common entries are not all that. [ItemStackHistoricalAttributeTooltipMixin:20,52–62](../../src/main/java/net/historicalexperience/mixin/ItemStackHistoricalAttributeTooltipMixin.java#L20-L62) targets common `ItemStack`; its *dependency* is client presentation code. Client-array relocation is sensible for that presentation hook, but the reason is different from missing target classes. Actual common/client lists are [JSON:5–99](../../src/main/resources/historical_experience.mixins.json#L5-L99). Preserve each entry's intended environment independently of folder name; moving a common server hook into `client` silently removes dedicated-server enforcement. Audit the Moderner Beta biome hooks already in [client:104–106](../../src/main/resources/historical_experience.mixins.json#L104-L106) rather than treating folders as proof of correct side.

No inherent target-method remapping change follows from moving a mixin. However fully qualified descriptors/imports/accessor references, generated mapping/refmap artifacts if applicable, and transformed direct static invoker calls must be regenerated and verified in the packaged/remapped artifact, not assumed safe from source compilation. Test one-to-one JSON/class membership, no duplicates, side-target dependencies, dedicated-server boot AND client boot, plus actual container click and both probe invocations. A plain boot cannot catch the documented deferred helper failure.

## SHOULD

### S1 — Correct the performance claim; preserve already-cheaper render fast paths

A resolved immutable version reference is a clear improvement over repeated id→HashMap→Optional and two-bound comparisons in the [gate implementation:210–223](../../src/main/java/net/historicalexperience/gameplay/HistoricalGameplayTweaks.java#L210-L223). [Player combat:59–92](../../src/main/java/net/historicalexperience/mixin/PlayerHistoricalCombatMixin.java#L59-L92) repeatedly does that work; precomputed bit membership should be cheaper there. Nether/food paths also currently resolve on every call. No hot-path allocation or evaluation of windows should remain.

But “strictly cheaper than today's String switch + HashMap.get” is not universal: pre-Beta gates already perform set membership; some render paths are a **single cached volatile boolean** ([activeNow:93–94](../../src/main/java/net/historicalexperience/client/lighting/HistoricalOldLighting.java#L93-L94)). Replacing that getter with global volatile→null→EnumSet lookup adds work and can bypass toggle semantics. Keep `activeNow` caches and refresh/rebuild triggers; replace their *availability computation*. Capture the active version once in a multi-gate operation to avoid multiple volatile reads and internally inconsistent session answers. EnumSet is O(1), not guaranteed one physical CPU instruction; defensively copy once, never per query. Measure representative attack, food-merge, tick and block/render workloads before making a strict performance assertion.

### S2 — Persistence freeze must cover values and schemas, not counts

What is really stored/compared:

* Metadata emits **schema, profileId, generationPreset, metadata revision, history(revision,timestamp,actor,note), optional snapshotPatchId**, not chronology ([encoder:43–59](../../src/main/java/net/historicalexperience/world/metadata/MetadataJson.java#L43-L59)). Empty patch omission is intentionally canonical-byte stable. Do not serialize enum names/ordinals instead.
* Journal stores **schema, phase.name(), timestamp, backupDirectory, fromPreset, targetMetadataJson** ([journal:137–142](../../src/main/java/net/historicalexperience/world/upgrade/UpgradeJournal.java#L137-L142)). Preserve phase spellings, schema/recovery compatibility and target metadata identity.
* `level.dat` provider settings persist raw **`moderner_beta:preset`** aliases in chunk/biome/cave provider settings ([key:68](../../src/main/java/net/historicalexperience/world/upgrade/WorldGenSettingsAdvance.java#L68), [read:203–208](../../src/main/java/net/historicalexperience/world/upgrade/WorldGenSettingsAdvance.java#L203-L208), [write:491](../../src/main/java/net/historicalexperience/world/upgrade/WorldGenSettingsAdvance.java#L491)). They are not gameplay profile ids or upstream foundation ids interchangeably.
* The alias binding preserves profile id, upstream foundation, **generation recipe revision** and experimental flag ([profiles:117–145](../../src/main/java/net/historicalexperience/profile/HistoricalProfiles.java#L117-L145)). Metadata revision and generation revision are distinct counters ([upgrade:184–196](../../src/main/java/net/historicalexperience/world/upgrade/GenerationUpgrade.java#L184-L196)). Freeze resource IDs as well as Java strings. Source confirms chronology is derived, not persisted in the Alpha helper ([1370–1373](../../src/main/java/net/historicalexperience/version/HistoricalVersions.java#L1370-L1373)); world-package chronology hits are in biome classification, not serializers.
* Finite transition origin hashes the first metadata history entry ([identity:62–68](../../src/main/java/net/historicalexperience/world/upgrade/FiniteTransitionIdentity.java#L62-L68)). Existing history/notes must remain unchanged. New upgrade notes incorporate revision description ([upgrade:209–213](../../src/main/java/net/historicalexperience/world/upgrade/GenerationUpgrade.java#L209-L213)), so descriptions are not harmless cleanup during migration.

The proposed golden pins **exclusion and ore counts** ([115](target-architecture.md#L115)) can pass when a forbidden feature id changes or an ore height/count changes. Pin full ordered exclusion id/reason lists, every ore rule field, revision flags/descriptions, aliases/foundations, associated resource content and old-alias behavior. Chronology numbers must remain identical as *comparison contracts*, not falsely described as metadata fields. Freeze finite IDs/geometry and snapshot parent/selection ids too.

### S3 — Do less: boundary values, data extraction, domain-owned visual styles

* Cut the hand-maintained enum of **every registered build**. It duplicates registry declarations and adds an edit site per version—the problem this architecture was meant to remove. Simpler: immutable registered version identity plus explicit `Boundary` constants only for shared/undeclared/numeric-sentinel thresholds; ranges compare stable keys, exact rules compare identity. A typed enum is excellent for the finite **features**, not necessarily for every expandable historical build. If all-build Milestone is retained, generate it or require a bijection/duplicate/order test, and do not conflate enum order with the stable numeric scale.
* `VisualProfile` is optional convenience, not a demonstrated architectural need. The proposed Star/Tooltip/Sky/Colormap/Label mega-record couples independently owned client systems and can duplicate feature bits. Keep pure small style resolver enums in their domains, or precompute one compact presentation record only after a repeated version→styles computation is measured. Texture windows already work; preserve their tested priority engine rather than unify texture-layer policy into the gameplay feature enum. Keep availability separate from user activation.
* Extraction of revision recipes/data is justified; **`legacy/` and five family files are not necessary prerequisites**. First move carrier types and shared constants into pure version-data ownership and extract a revision builder. Keep one searchable composition root. Family files may follow if the resulting declarations remain too large. “Legacy” is a vague name for the entire actively supported product; `version.data`/`version.catalog` communicates ownership better. Do not declare dependency cycles solved merely by naming the core→legacy composition exception.
* Avoid broad dead-code/probe moves in the semantic gate migration. They increase blast radius while adding no boundary correctness. Keep provenance/licence headers and the existing probe property contract during later mechanical moves.

### S4 — Make the order change explicit, not hidden in a refactor

The current `all()` doc says oldest-first, but implementation appends declaration order unchanged ([ALL:1221](../../src/main/java/net/historicalexperience/version/HistoricalVersions.java#L1221), [getter:1870–1872](../../src/main/java/net/historicalexperience/version/HistoricalVersions.java#L1870-L1872)); it starts Beta1.7.3, Beta1.8.1, and appends early eras later. Existing [test profiles:47–50](../../src/test/java/net/historicalexperience/gameplay/HistoricalGameplayTweaksTest.java#L47-L50) explicitly sort it. The proposal corrects this contract, but then S0 snapshot cannot be strictly unchanged for enumeration consumers. `allRevisionAliases()` explicitly promises declaration order ([1889–1894](../../src/main/java/net/historicalexperience/version/HistoricalVersions.java#L1889-L1894)); marker derives that list. Inventory consumers and either preserve `all()` during the semantic migration plus add `chronological()`, or approve/test a separate ordering diff. Freeze clone construction order too: Alpha1.2.2a currently uses the previously appended Alpha1.2.0 object ([877–883](../../src/main/java/net/historicalexperience/version/HistoricalVersions.java#L877-L883)); sorting or splitting before construction must not change which base is cloned.

## NICE

1. Generated matrix and dependency lints are welcome, but use stable ordering, explicit unknown/evidence status and an opt-in update command. A stale-doc test must not silently rewrite golden behavior. Distinguish “matches current implementation” from “historically verified”.
2. Add a polarity/category field to migration documentation (deviation/capability/data query/algorithm/context); do not burden runtime Feature with a generic expression language to support adapters that should stay ordinary methods.
3. Keep minimal mixin thunks, but avoid a mass package rename just for aesthetics. Domain folders are useful only if their JSON/import/remap maintenance cost is paid and runtime probes remain intact.

## Explicit agreement with the proposal

* Typed `Feature` constants eliminate string-key typos and enable exhaustive coverage beyond the incomplete current `gateNames()` list.
* Central, evidence-bearing **current-code** boundaries; half-open windows, unions, and exact identity are appropriate for the demonstrated gate shapes.
* Negative historical deviations defaulting inactive in ordinary/unknown sessions are a strong runtime API, provided positive capabilities remain correctly inverted adapters and old sword blocking is not inverted.
* Resolve known session ids once and precompute immutable answers; retain pure explicit-version APIs for tests and world-aware contexts for enforcement.
* Keep per-version simulation data distinct from immutable append-only generation revisions. Never let a gameplay-feature refactor rewrite old generation recipes.
* Preserve generator-sourced truth, alias binding identity, fail-closed marker decisions, snapshot overlays and journal/recovery separation.
* Extract shared data/recipe responsibility from the oversized registry and remove dependency cycles using genuinely pure carrier ownership.
* Keep texture layering central, algorithms in their domains, and mixins thin; correct client-only dependency registration with dedicated-server evidence.
* S0 characterization before implementation, focused commits, isolated deliberate bug fixes, and separate unit/runtime acceptance are the right overall migration discipline—after the safety gaps above are closed.
